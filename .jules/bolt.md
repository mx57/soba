
## 2026-06-25 - [SQLite Optimization in DataStore]
**Инсайт:** Открытие и закрытие соединения SQLite на каждую запись (log_event) создавало значительные накладные расходы (overhead), особенно при частом логировании. Использование режима WAL (Write-Ahead Logging) и синхронизации NORMAL в сочетании с постоянным соединением дает колоссальный прирост скорости записи.
**Действие:** Всегда использовать пул соединений или одно постоянное соединение для локальных БД SQLite, если приложение предполагает частые мелкие записи. Не забывать про PRAGMA journal_mode=WAL.

## 2026-06-25 - [Math Optimization in InputManager]
**Инсайт:** Использование `**2` и `**0.5` (или `math.sqrt`) в обработчиках событий мыши, которые срабатывают сотни раз в секунду, создает избыточную нагрузку на CPU. Прямое умножение `x*x` и сравнение квадратов расстояний позволяет избежать вычисления квадратного корня и общих операций возведения в степень.
**Действие:** В "горячих" участках кода (обработчики UI-событий, циклы анимации) заменять `**2` на `x*x` и по возможности использовать сравнение квадратов для проверки расстояний.

## 2026-06-27 - [Batching SQLite Updates for High-Frequency Progression Systems]
**Инсайт:** Запись в SQLite каждые 500-1000мс (даже в режиме WAL) при активном взаимодействии пользователя создает ненужную нагрузку на I/O. Буферизация очков в памяти и сброс (flush) в БД пачками (например, раз в 10 единиц или при закрытии) значительно снижает количество транзакций без потери пользовательского опыта.
**Действие:** Всегда буферизировать инкрементные данные (очки, опыт, валюта) и записывать их в БД только по достижении порога или при наступлении ключевых событий (выход, милстоун).

## 2026-06-28 - Оптимизация UI-событий в PySide6
**Инсайт:** Частые вызовы системных методов, таких как `self.pos()` или `mapFromGlobal()`, внутри обработчиков движения мыши или циклов отрисовки (12+ FPS) создают значительную нагрузку на CPU.
**Действие:** Кэшировать позицию окна через `moveEvent` и вычислять локальные координаты математически на основе глобальных координат курсора. Это на порядки быстрее, чем вызов `mapFromGlobal`.

## 2026-06-28 - Сигналы и слоты в PySide6/PyQt
**Инсайт:** Сигнал `triggered` у `QAction` по умолчанию передает boolean-флаг `checked`. Если слот не принимает этот аргумент, возникнет `TypeError`.
**Действие:** Всегда определять слоты для действий меню с аргументом `checked` или использовать lambda-заглушки для игнорирования аргумента.

## 2026-06-29 - [QPixmap Caching in Procedural Animation]
**Инсайт:** При использовании процедурной анимации (12+ FPS) через QSvgRenderer, создание нового QPixmap в каждом кадре приводит к избыточным аллокациям памяти и нагрузке на CPU. Кэшировать QPixmap и его пересоздание только при изменении размера окна (resizeEvent) значительно повышает плавность.
**Действие:** Всегда кэшировать тяжелые объекты отрисовки (QPixmap, QImage) в методах update_frame и paintEvent, если их параметры не изменились.

## 2026-06-29 - [Qt StyleSheets and Opacity]
**Инсайт:** Стандартные виджеты Qt (QLabel, QWidget) не поддерживают свойство 'opacity' через QSS (Qt Style Sheets), в отличие от веб-технологий. Использование этого свойства игнорируется без ошибок.
**Действие:** Для изменения прозрачности текста или элементов UI использовать явное задание цвета с альфа-каналом (rgba) или QGraphicsOpacityEffect.

## 2026-06-30 - [Immediate Achievement Triggering with Buffered Data]
**Инсайт:** При использовании буферизации данных в памяти для оптимизации SQLite (например, запись пачками), проверка условий достижений напрямую через БД становится "ленивой" — достижения не срабатывают в момент реального выполнения условия.
**Действие:** Всегда вызывать принудительный сброс буферов (flush) непосредственно перед запуском логики проверки достижений. Это гарантирует мгновенную реакцию системы на действия пользователя при сохранении преимуществ буферизации для частых мелких обновлений.

## 2026-07-01 - [Correct Application Exit in Tray-based Apps]
**Инсайт:** При использовании `QApplication.setQuitOnLastWindowClosed(False)` обычный вызов `self.window.close()` может не завершить процесс, а прямой вызов `QApplication.quit()` может пропустить важные события закрытия (например, `closeEvent`), в которых происходит сохранение данных.
**Действие:** Для корректного выхода из трея использовать последовательный вызов: сначала `window.close()` для триггера сохранения, затем `QApplication.quit()` для завершения процесса.

## 2026-07-02 - [High-Performance Achievement System with In-Memory Checks]
**Инсайт:** Проверка условий достижений через прямые SQL-запросы в "горячих" путях (например, при каждом клике или движении мыши) создает неоправданную нагрузку на диск. Буферизация статистики в памяти и выполнение проверки достижений на основе комбинированных данных (БД + память) позволяет полностью исключить SQL-транзакции из основного цикла.
**Действие:** Реализовать check_achievements как чистую функцию, принимающую словарь статистик. В InputManager собирать этот словарь из кэша и буферов перед проверкой. Вызывать flush_all() только при реальном открытии нового достижения для минимизации I/O.

## 2026-07-04 - [Atomic Batch Updates for Statistics]
**Инсайт:** Использование отдельных SQL-запросов для обновления каждой характеристики (очки, клики, KPS) при сбросе буфера (flush) неэффективно. Группировка всех обновлений в одну транзакцию через BEGIN TRANSACTION/COMMIT (метод update_stats_batch) значительно снижает нагрузку на диск и гарантирует атомарность данных.
**Действие:** При необходимости обновления нескольких полей в БД SQLite (например, при сбросе игрового прогресса из памяти) всегда использовать транзакционный пакетный метод вместо последовательных вызовов increment_stat.

## 2026-07-05 - [Code Quality: Redundant Event Logging]
**Инсайт:** Логирование событий одновременно в UI-слое (TrayMenu) и в слое логики (InputManager) приводит к дублированию записей в БД. Это замусоривает историю и может сбивать пользователя с толку.
**Действие:** Централизовать логирование ключевых событий (level_up, achievement) в InputManager. В TrayMenu логировать только те действия, которые инициируются напрямую пользователем через меню (кормление, запуск таймера).
